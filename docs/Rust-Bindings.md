
# Rust Bindings

Write your AromaUI app in Rust. You get the same windows, widgets, and
themes as C (buttons, labels, containers, and fonts), callable directly from
Rust. When the framework updates, one command refreshes the bindings, so
your code keeps working.

The bindings are generated by `tools/generate_rust_bindings.py` on top of
the vendored `ctypesgen` C parser -- the same backend as the Python
bindings. Nothing is hand-written: `src/ffi.rs` is translated from the
public C headers on every run.

## Getting Started

```bash
git submodule update --init vendors/ctypesgen
aroma bindings --language rust --check
```

If that prints `crate ok; functions=... structs=... enums=...`, you are
ready. The `ERROR:` / `WARNING:` lines above it (unparsable `_Alignas`
fields, glibc internals, function-like macros) are normal parser noise from
`ctypesgen` -- generation succeeds as long as it ends with
`wrote ... (63 headers, ...)`.

Now run the hello example (from the repo root, after building
`libaroma.so`):

```bash
AROMA_LIB=$PWD/build/src/libaroma.so cargo run --manifest-path bindings/rust/Cargo.toml --example hello
```

(`build/src/libaroma.so` is your framework build.)

## Creating a Rust Project

```bash
aroma create myapp --rust
cd myapp
aroma run linux
```

This scaffolds `src/main.rs` (a tap-counter hello app) and `Cargo.toml`
with a path dependency on the generated `aroma` crate. `aroma build linux`
generates `bindings/rust` from the C headers, builds `libaroma.so` once
into `build/aroma-lib/`, then runs `cargo build`; `aroma run linux` runs
it. The first build takes several minutes (it compiles freetype from
source) -- wait for `OK Build successful` at the end. Only the Linux
desktop target is wired for Rust so far -- Android and
Web builds report an error instead of failing obscurely halfway through.

## First Application

```rust
use aroma::{ffi, ui_button, ui_container, ui_create_window, ui_init,
            ui_is_running, ui_label, ui_process_events, ui_render};
use std::ffi::CString;
use std::os::raw::c_void;

extern "C" fn on_tap(_node: *mut ffi::AromaNode, _ud: *mut c_void) -> bool {
    println!("tapped");
    true
}

fn main() {
    unsafe {
        assert!(ui_init(), "aroma_ui_init failed");
        let theme = ffi::aroma_theme_create_material_blue_dark();
        ffi::aroma_theme_set_global(&theme);
        let font_path =
            CString::new("/usr/share/fonts/truetype/dejavu/DejaVuSans.ttf").unwrap();
        let font = ffi::aroma_font_create(font_path.as_ptr(), 20);
        let window = ui_create_window("Hello", 400, 600);
        let root = window as *mut ffi::AromaNode;
        let bx = ui_container(root, 0, 0, 400, 600);
        ui_label(bx, "Hello, Rust", 40, 60, 1, font);
        ui_button(bx, "Tap me", 40, 140, 200, 52,
                  Some(on_tap), std::ptr::null_mut(), font);
        while ui_is_running() {
            ui_process_events();
            ui_render(window);
        }
    }
}
```

The pattern is always the same: init, create a window, add widgets,
loop over events + render. Compare with the C version in
[Getting Started](../overview/Getting-Started.md) and the Python version in
[Python Bindings](Python-Bindings.md): the calls match, in the same order.

## Usage Guidelines

- **Refresh after updating.** The bindings are generated files (never
  committed, under `bindings/`). After pulling new framework code, run
  `aroma bindings --language rust` again so Rust matches it.
- **Raw vs safe.** `aroma::ffi` is the raw `extern "C"` translation
  (`src/ffi.rs`); `aroma::{ui_init, ui_button, ui_label, ui_container, ...}`
  are safe ports of the C `static inline` helpers from `aroma_ui.h`
  (`src/lib.rs`). Those inlines have no symbols in the `.so`, so -- like
  the Python bindings -- the wrappers call the same `*_impl` /
  `aroma_*_create` entry points.
- **Text is `&str`.** The `ui_*` helpers take Rust `&str` and convert to
  `CString` for you; raw `ffi` functions take `*const c_char`.
- **Callbacks are `extern "C" fn`.** Keep them as plain functions (like
  `on_tap` above). Closures cannot cross the C boundary directly; box and
  pass state via the `user_data: *mut c_void` pointer instead.
- **All FFI calls are `unsafe`.** Dereferencing window/node pointers and
  calling into `libaroma.so` requires `unsafe`, as usual for `extern "C"`.

## Generated Files

`aroma bindings --language rust` writes a crate next to your project
(`bindings/rust/` by default):

- `Cargo.toml` / `build.rs` -- link against `libaroma`
  (`AROMA_LIB` points at your build; `build.rs` probes `build/src/` for
  `libaroma.so` first, then falls back to the default static
  `build/src/libaroma.a`).
- `src/ffi.rs` -- raw bindings (structs, enums, `extern "C"` functions).
- `src/lib.rs` -- safe `ui_*` wrappers.
- `examples/hello.rs` -- the app above.

Useful flags: `--output` to choose where the crate goes, `--check` to
verify it (`cargo metadata` runs too when cargo is on `PATH`), `--stats`
to peek at what's inside without writing files. The standalone tool takes
the same flags:

```bash
python3 tools/generate_rust_bindings.py --output bindings/rust --check
python3 tools/generate_rust_bindings.py --stats
```

## Troubleshooting

| You see | Do this |
| --- | --- |
| `No public headers (aroma*.h)` | Run from the repo root or pass `--include-dir` pointing at the SDK `include/` |
| `ctypesgen submodule is empty` | `git submodule update --init vendors/ctypesgen` |
| `aroma` doesn't know `--rust` / takes the C build path for a Rust project | Your installed `aroma` (`~/.aroma`) is older than the repo. Re-sync it (`cp -a tools/cli/. ~/.aroma/tools/cli/` plus `tools/generate_*_bindings.py`, `include/`, `src/`) or reinstall the SDK, then retry |
| `AROMA_LIB=... does not exist; ignoring` | That path doesn't exist; drop the override and let `build.rs` find the lib (`build/aroma-lib/src/` in the project, `build/src/` in the SDK) |
| `libaroma.so not found` / link errors | `build.rs` uses `build/src/libaroma.a` automatically when no `.so` exists. For a shared lib: `cmake -S . -B build -DBUILD_SHARED_LIBS=ON && cmake --build build`, or set `AROMA_LIB` to its full path |
| `cargo: command not found` under `aroma` (but `cargo` works in your terminal) | Your shell finds cargo via `~/.cargo/bin`, which non-interactive shells don't inherit. Either `export PATH="$HOME/.cargo/bin:$PATH"` first or add it to `~/.profile` |
| `cargo: command not found` anywhere | Install the Rust toolchain (`rustup`), then re-run `--check` |
| `vk*` undefined symbols at link time | Your `libaroma.a` was built with Vulkan support but `-lvulkan` wasn't linked. Regenerate bindings (`build.rs` now links it) and rebuild |
| Taps stop working | Your callback was dropped. Keep `extern "C" fn` items at module level |
